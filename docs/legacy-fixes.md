# 原版 sb.sh 高风险问题修复记录

范围：VPS 用的 `sb.sh`。这是针对具体触发路径的修复，不是全项目安全认证；未审计 Serv00 全套脚本和预编译辅助程序。

## 本轮修改

| 问题 | 原行为 | 修改后 |
| --- | --- | --- |
| 订阅路径越界删除 | 未验证的旧路径密码拼接到 `rm -rf /root/websbox/...`，`../` 可越界 | 新旧路径都限制为 16–128 位字母、数字、下划线、连字符；拒绝符号链接根目录；非法参数在删除前返回 |
| 订阅口令复用、端口输入无校验 | 默认复用代理 UUID，任意端口文本进入 HTTP 启动参数 | 默认生成独立随机口令；当前输入与持久化端口都校验为 1–65535 |
| UUID/WS 路径拼入 sed | 特殊字符破坏替换表达式或 JSON，固定行号可能改错字段 | 按 JSON 字符串键和值做替换，保留行布局；验证 UUID 和兼容的 URL 路径字符；先生成全部候选配置，用内核校验活动配置，再备份与替换 |
| 修改后启动失败 | 原凭据配置已经被覆盖 | 保存三份配置的 `.credentials.previous` 备份；启动失败尝试恢复并重启；重启检查进程是否稳定，避免刚崩溃又拉起时误报成功 |
| Argo 下载损坏现有文件 | 直接写目标路径，没有可靠检查，失败后继续启动 | 临时文件下载，HTTPS 校验、失败码、超时和 `--version` 检查；失败不替换原文件，调用者停止后续操作 |
| 凭据进入生成脚本 | Argo Token、Telegram Token/ID 未校验就写入服务脚本 | 在写文件和停止旧隧道前验证输入；不回显 Token，限制已有凭据文件权限 |
| GitLab 命令拼接和远端覆盖 | 生成含用户输入的 expect/Bash 脚本、强制推送、重建本地历史 | 使用参数数组调用 Git，不执行旧 expect 文件；检查分支；保留历史，普通推送冲突即停止；不再修改全局 Git 身份 |
| GitLab 凭据传播与错误报成功 | 推送令牌进入远程 URL/订阅 URL；推送错误可能被掩盖 | 用受限文件和静态 askpass 提供推送令牌；私有订阅要求独立只读令牌，公开仓库无需订阅令牌；只提交三个订阅文件，推送失败明确返回失败 |

WS 路径目前接受常见路径及查询字符，例如 `/proxy?ed=2048&x=1`。拒绝原订阅手工拼接无法可靠处理的引号、反斜线、空白、双斜线等；需要特殊字符时使用适合实际协议的百分号编码。原文件其他菜单仍使用固定行号，所以本轮没有用 jq 重新格式化整个配置。

原 GitLab 设置需重新配置一次，才能使用新的分支记录和 askpass。私有仓库的只读令牌权限必须由用户在 GitLab 限制；脚本只能要求与推送令牌不同，不能仅凭令牌字符串证明实际权限。订阅 URL 仍是敏感信息，不能公开。历史上已经泄露的令牌需要在 GitLab 撤销，修改脚本不能收回旧令牌。

## 之前已修复

取消默认关闭防火墙、清空规则和停用 Apache；本地快捷脚本不再被上游 main 自动覆盖；内核下载使用临时目录并检查兼容性，升级保留活动配置与旧内核；停用未审计辅助二进制自动下载；链式接管标记阻止本分支旧菜单继续操作。

## 验证

```bash
bash -n sb.sh
python3 -m unittest discover -s tests -v
python3 -m unittest discover -s chain/tests -v
```

测试只提取待测函数，在临时目录运行，不 source 整个安装器，不操作真实系统服务，不向 GitLab/Telegram 发送请求。除输入、文件保留、回滚和进程检查外，还通过临时本地 Git 远程确认：额外暂存的私钥不进入订阅提交；远端有其他提交时推送失败且远端历史不变。

## 仍需注意

- 本地 IP 订阅依然使用 HTTP，路径密码不提供传输加密；建议通过受控 HTTPS 分发。
- 其他域名、端口、分流菜单仍有固定行号编辑，尚未全面迁移到结构化配置事务。
- Argo 仍采用原来的 Token 启动参数，文件不回显和权限限制不能消除进程参数暴露面；后续可迁移到支持版本的 token-file。
- 动态 cloudflared/历史内核下载目前依赖 HTTPS 与可执行文件检查，尚未使用完整版本哈希锁；新链式内核有独立哈希锁。
- ACME、WARP、BBR 等外部脚本和旧定时任务未完成全面审计；本轮没有运行它们。

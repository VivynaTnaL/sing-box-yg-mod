# 独立链式附件：实现与验证

本分支的交接格式是标准 sing-box 配置。配置生成、附件导入、运行管理和客户端订阅分别有独立入口；使用方法见 [ADDON.md](../chain/ADDON.md)。

## 约定需求

| 需求 | 实现 | 已执行的验证 |
| --- | --- | --- |
| 不依赖原配置生成器 | 导入服务端入站及证书，保存独立快照；公网地址由用户补充 | 删除源配置及证书后，五协议仍可构建与导出 |
| 附件与原运行时独立 | 独立端口、凭据、内核、服务、状态；A 只经 B 出站 | 原服务与附件并行的真实 TCP/UDP 流量；B 故障、错误密钥与停止附件均不影响原服务 |
| 方便回到原服务 | 新模式只需停止附件；旧接管版有显式恢复入口 | 隔离服务管理测试覆盖配置校验、恢复、失败回滚和标记保留 |
| 原脚本生成与运行拆分 | 旧模板抽为纯模块，安装分阶段；独立只生成向导和参数文件入口 | 两套模板与原内容一致；生成失败不调用部署；脱离仓库的快捷入口测试 |
| 简化操作 | `sb-chain` 中文菜单、五协议生成向导，CLI 留给自动化 | 菜单复用同一命令处理；向导与参数入口测试 |
| 服务器 URL 订阅 | Mihomo、sing-box、URI、Base64 四类文件；随机口令、稳定 URL、HTTP/HTTPS | 真实 GET/HEAD、证书校验、更新、旧口令失效、私密文件不可访问 |
| A、B、A→B 独立订阅 | `A-direct`、`B-direct`、`A-to-B` 各自四种文件与固定 URL；保留合并订阅 | 分组 GET/HEAD、增删、稳定 URL 更新与口令轮换；旧 manifest 兼容；路径遍历和各层符号链接拒绝；整代失败回滚 |
| 跨机交换直连节点 | B 在本机由服务端配置导出标准客户端交换文件，A 导入并应用直连组 | 五协议真实内核检查；删除 B 源配置及证书后仍保留原指纹；导入失败不修改状态；并发导出不覆盖已有文件 |
| 国内和局域网排除 | 客户端域名/IP 规则与 DNS 分流；支持直连和代理例外 | 三模式完整规则通过两客户端内核检查；真实 TCP/UDP 选择直连和代理出口 |
| 自动获取 GeoIP/GeoSite | 同一 GitHub release 的两个固定资产，大小与 SHA-256 校验，转换为内嵌 CN 规则 | 真实两库下载和转换；损坏、半下载、限流和转换失败测试 |
| 规则自动更新 | 首次构建自动获取，手动刷新和独立每日 timer，失败保留有效快照 | 定时器隔离测试；版本不变复用；更新不重启代理、不发布待部署凭据 |
| 操作失败可恢复 | 服务配置、订阅 manifest 与管理状态联合回滚 | 最后一次状态写入失败仍恢复原服务配置、订阅和 metadata |

## 已部署版本升级与三组订阅

A、B 已初始化部署时，先更新仓库，再在各自原 `--state` 目录执行 `install` 更新工具。首次升级到能记住目录的版本时，自定义目录用户需要执行一次 `./sb-chain --state /root/addon-state install`，将路径换成各自的原状态目录。无需重新初始化或重新部署代理。

在 B 执行 `export-nodes` 导出原 B 服务的客户端连接信息，通过 SSH/SFTP 交给 A；A 用 `add-direct` 读取本机原服务配置，用 `import-nodes` 接收 B 文件，然后执行 `publish-clients`。该操作只应用直连组，保留已部署的 A→B 节点和分流规则，不重启代理，也不发布待部署的入口或密钥变更。

在 A 设置订阅发布后，三组分别使用 `/<口令>/A-direct/<文件名>`、`/<口令>/B-direct/<文件名>`、`/<口令>/A-to-B/<文件名>`。每组支持四种客户端文件，原 `/<口令>/<文件名>` 合并地址继续有效。已运行旧订阅模块的用户需按原参数重新执行一次 `publish`，以加载新版分组路由。

完整升级命令、跨机文件传输及 HTTPS 配置见 [ADDON.md 的三组订阅教程](../chain/ADDON.md)。A、B 原服务需继续运行才能提供各自直连节点；B 附件链路端口仅供 A 使用。

## 安装后记住状态目录

成功安装会在 `/etc/sing-box-addon/manager.json` 保存版本号和状态目录绝对路径。该文件在 `Runtime.install` 的全局锁和文件事务内更新，安装失败时恢复此前的记录；卸载保留记录，便于从仓库重新安装。

系统 `sb-chain` 和仓库 `./sb-chain` 共用目录选择规则：本次显式 `--state` 优先，其次是安装记录；没有记录时使用原默认 `/etc/sing-box-addon`。普通命令不会改写记录，只有成功 `install` 才会记住新的目录。菜单及 `status` 显示实际目录；设置损坏或记录指向的目录丢失会明确报错，可显式指定原目录检查并重新安装修复。
若设置路径本身为符号链接或目录，需先处理异常路径，安装不会覆盖它；普通管理命令仍可通过显式 `--state` 访问原部署。

完成一次安装记录后，`sb-chain`、`sb-chain status`、`sb-chain urls` 和后续 `./sb-chain install` 可以省略目录参数。此前设置过带 `--state` 的 shell 别名的用户，需要执行 `unalias sb-chain` 并删除 `~/.bashrc` 中对应旧行，才能验证新默认；未设置过别名的用户不需要这一步。

这是管理入口的默认目录设置。当前后台仍为全机单实例，记住或覆盖管理目录不会重新部署代理，也不会让已保存的规则定时任务改用另一份状态。

## 复现命令

在完整仓库执行，替换实际内核路径：

```bash
python3 -m unittest discover -s tests
SB_TEST_CORE=/path/to/sing-box-1.14.0 CHAIN_TEST_CORE=/path/to/sing-box-1.14.0 \
  python3 -m unittest discover -s chain/tests
python3 chain/tests/integration_addon.py --binary /path/to/sing-box-1.14.0
python3 chain/tests/integration_publish_tls.py
bash -n sb.sh lib/sb-config.sh lib/sb-install.sh sb-chain
```

网络集成测试只绑定回环地址，全部文件和进程使用临时目录，不调用真实系统服务。本轮还使用 GitHub 真实数据，在 sing-box 1.14.0 和 Mihomo 1.19.31 上检查了五协议、三组独立配置、三种分流模式。

## 验证边界

代码实现和上述本机验证已经完成。没有据此将工作区改动安装到当前服务器，也没有完成两台真实 VPS 与手机客户端的公网验收。目标机器的 systemd、端口开放、NAT 来源、域名/证书和客户端内核支持，仍要在实际部署时确认。

附件不接管原 ACME、WARP、CDN 或 Argo 的运行流程。导入的证书是快照，续期后需要重新导入；纯 URI 订阅不携带分流规则。sing-box 客户端文件默认提供 mixed 入口，TUN/手机客户端需按客户端入口要求接入。后台安装支持 systemd 247+；独立生成和导出不要求启动后台服务。
